# JY61P_OLED_MSPM0G3507

这是给天猛星 MSPM0G3507 扩展板准备的 JY61P + OLED 测试工程框架。

目标很简单：

- JY61P 走 UART0，接 PA0 / PA1，默认波特率 9600
- OLED 走 I2C0，接 PA28 / PA31
- 开机后在 OLED 上显示 Roll / Pitch / Yaw
- 支持串口发零偏命令，并在软件里保留 Yaw 零位
- OLED 额外显示帧计数、校验错误计数、串口错误计数

## 现在这个工程里有什么

- `main.c`：新的测试入口
- `src/drivers/jy61p.c/h`：JY61P 串口协议解析桥接
- `src/drivers/oled.c/h`：OLED 的桥接文件
- `delay.c/h`：简单延时

## 复用关系

- 真实可复用协议代码放在 `Modules/Drivers/JY61P/`
- 工程里的 `src/drivers/jy61p.c` 只是 CCS 兼容桥接
- OLED 继续复用现有 `Modules/Drivers/OLED/`

## 你还需要在 CCS 里确认的 SysConfig

这个目录已经把源码框架整理好了，但要真正编译和上板，还需要在 CCS 里把 SysConfig 设成：

- UART0 -> PA0 / PA1，波特率 9600
- I2C0 -> PA28 / PA31
- 保持 LED / 其他板级资源不冲突

如果后面要兼容 MPU6050 测试，也建议保留 PA0 / PA1 这组引脚作为“陀螺仪接口复用口”，只是驱动在 JY61P / MPU6050 之间切换。

## 测试顺序建议

1. 先只开 UART0 接收，看 JY61P 帧有没有进来。
2. 再开 OLED，确认 Roll / Pitch / Yaw 能显示。
3. 再做零偏命令和 Yaw 归零。
4. 最后再接路径控制、航向控制。

## 本次补强的调试点

- `F:` 帧计数：确认 JY61P 是否持续输出数据
- `C:` 校验错误计数：确认帧校验是否稳定
- `R:` 串口错误计数：确认串口中断/接收流程是否异常
- 自动零偏：上电后延时一次执行零点命令，方便直接看归零效果
- `Yaw` 采用 0.1° 显示，便于观察小角度漂移和回正误差

## 为什么之前看起来“没通信”

这部分是我们这次实测后补上的排查结论，后面队友如果再遇到同样的问题，可以直接先看这里：

- 串口助手中已经能看到 JY61P 持续输出 `55 51 / 55 52 / 55 53 / 55 54`，所以模块本身是工作的；
- MCU 端只要 `RX` 计数和 `F53` 帧计数都在涨，就说明接收和 `0x55 0x53` 角度帧识别正常；
- `YawRaw` 随转动变化，说明字节顺序和解帧逻辑也正确；
- 早期之所以“像没通信”，主要是因为显示方式把原始字节、整数角度和浮点角度混在一起了，看起来像没变化。

正式测试时，优先盯这四个量：

1. `RX`
2. `F53`
3. `YawRaw`
4. `YawDeg`

只要这四项都正常，就可以判断 JY61P 的通信链路已经跑通。
