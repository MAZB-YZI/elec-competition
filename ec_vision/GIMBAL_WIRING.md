# 云台接线与联调手册(F32C 无刷电机版)

> 硬件: **WHEELTEC F32C TTL 无刷总线电机 ×2**(二自由度云台)。
> 本手册所有协议/单位/接线均已用厂商《F32C无刷电机使用手册 V1.0》《F32C二自由度云台
> 使用手册 V1.0》+ 官方例程 MiniBalance.c 逐帧核对, 驱动 `f32c.py` 字节级对拍通过。
> PWM 舵机方案保留为备用(Drv=0), 见文末附录。

> ### ⚠ 血泪教训(2026-07-15)
> 1. **ID1(X/YAW)电机已被 60V 烧毁** —— 电源没调压就上电。F32C 额定 8~15V,
>    **内部无防反接、无过压保护**。每次接电机前先用万用表量一遍电源输出电压。
> 2. **GND 必须接!** 只接 RX/TX 不接 GND = 信号没有回流路径, 电流从相机 IO 保护二极管
>    灌进去: 既收不到反馈, 又可能让相机重启。相机 GND、电机 GND、12V 电源 GND 三者必连,
>    **哪怕相机是自己独立供电也必须共地**。
> 3. **实测确认: ID1 就是相机重启的元凶。** 拔掉 ID1 后同样的脚本一次跑通、反馈正常。
>    被 60V 打过的电机, 只要还挂在总线上, 一旦被请求反馈就会驱动 TX 线并把相机搞崩。
> 4. **被 60V 打过的电机, TX 脚绝对不要再接相机** —— 它可能在输出远超 3.3V 的电压,
>    会把相机的 UART 引脚也打坏。

## 1. 接线(MaixCAM2 直驱, Drv=1)

电机"接口一"是 GH1.25-5Pin, 手册线序(从左到右)= **GND · V+ · RX · TX · GND**。
配套单头杜邦线颜色: **红=V+ 黄=RX 绿=TX 黑=GND**。

```
F32C 电机接口一          线色    接到                         12V 电源
──────────────────────────────────────────────────────────────────────
V+          ──────────  红  ──────────────────────────────  12V+
GND         ──────────  黑  ──┬──  任一 GND 引脚 ──────────  12V-
RX(电机收)  ──────────  黄  ──┼──  A30 (UART1_TX)   ← 板发→电机收
TX(电机发)  ──────────  绿  ──┴──  A31 (UART1_RX)   ← 电机发→板收
```

- **12V 只进电机 V+, 绝不允许碰 MaixCAM2 任何引脚**(板子 IO 是 3.3V, 电机 TTL 也是 3.3V)。
- ⚠ **电机内部无防反接保护**: 电源线接反 = 烧电机。上电前务必核对红=V+/黑=GND。
- **必须共地**: 电机 GND、12V 电源 GND、MaixCAM2 GND 三者连通(手册: TTL 需与电机电源共地)。
- **不支持热插拔**: 先插好线再上电。
- 两只电机 RX 并 RX、TX 并 TX(总线并联), 靠地址区分(YAW=1, PITCH=2), 不用分开接。
- **A30/A31 与 PWM6/7 复用**: 用 F32C 就不能同时接 PWM 舵机(本来也不需要)。主控走左排 UART2(B0/B1) 不冲突。
- ✅ **A30=UART1_TX / A31=UART1_RX 映射已实机验证通过**(2026-07-15, 收到 ID2 电压与角度
  反馈)。节点 `/dev/ttyS1` 正确。**不需要对调信号线。**

## 2. 上电与联调顺序(逐步有判据, 别跳步)

1. **电机 12V 先上电, 等 5 秒**(电机控制器要初始化; 官方例程等 1.5s, 保守取 5s)。
2. **跑隔离测试**: MaixVision 运行 `f32c_test.py`, 全程打印收发帧 hex。
   - 电压反馈 ≈ 供电电压(约 12V) → 总线双向通、协议对、共地没问题, 一次全验。
   - `RX(raw)` 全程为空 → 对调黄/绿两根线重试; 仍不行查共地/电机 ID/波特率。
   - 扫摆时**记录**: YAW 角度增大往哪转、PITCH 角度增大抬头还是低头。
   - 只有一个电机动 → 另一个 ID 不对(需厂商 Windows 上位机确认 YAW=1, PITCH=2)。
3. **进框架**: 运行 `main.py`, 触屏切 GIMB。入模式瞬间云台应回零位并带保持力矩。
4. **方向标定**: `Src=1`(跟靶心), 靶纸放画面右侧, `FKp` 先调到 0.02。
   偏差条应缩短; 若云台背着靶跑、info 行出现 `LIM` → 切 `InvX`。Y 轴同理。
5. **增益整定**: 见下面第 5.5 节 —— **这是 PI 环不是 PD 环, 振荡要降 FKp, 加 FKd 没用**。
6. **限位确认**: `YawLim/PitLim` 按机械结构和排线余量设。**多圈电机会无限旋转,
   不设限位会绞断相机排线** —— 这是软件里唯一的硬保护, 务必留余量。
6.5 **单轴调试注意**: 只有 PITCH 在线时, **靶纸必须上下移动**才会看到云台响应;
   左右移动是 YAW 的活, 不会有任何反应, 不是坏了。

7. **校靶**(装激光后): 云台锁定时切到 TARG 页读 dx,dy(激光相对靶心偏差, px),
   填入 `AimOfX/Y`。视差随距离变, 固定距离打靶一次标定即可。

## 3. 位置模式: 直通 vs T型(PosMd 参数)

手册对多圈位置控制给了两种子模式, 二者行为差别很大:
- **PosMd=3 多圈直通**(默认): 无内部轨迹规划, 电机直接朝目标位置跟随。手册原话
  "**若需要高频率的发送改变目标位置, 建议选择直通模式**" —— 正是视觉伺服每帧改目标的场景。
  我们的外环已用 `FStep` 自己限速平滑, 不需要电机再叠一层 T 型规划的延迟。
- **PosMd=1 多圈T型**: 每个目标触发梯形加减速规划, 启停更柔和。官方例程 MiniBalance.c
  用的就是这个, 连续发也能跑, 但对快速伺服会引入一点滞后。

**默认 3。** 若实机上直通感觉发抽/过冲难压, 触屏把 PosMd 切到 1 再试(改后重启生效)。

## 3.5 单轴运行(某个电机烧了/拆了)

`Axes` 参数: **3=双轴(默认) 1=仅YAW(X,ID1) 2=仅PITCH(Y,ID2)**。改后重启生效。

设对以后, 驱动全程不会向离线地址发任何一帧, 也不等它的反馈、不给它算限位,
`LOCK` 判稳也只统计在线轴(否则离线轴误差永远收不掉, 永远不会 LOCK)。
**烧掉的电机必须整个拔掉(电源线 + 信号线都拔)**, 不能只是不发指令就留在总线上:
死掉的驱动芯片可能把共用的 TX 线拉住, 好电机的反馈也会一起收不到。

## 3.8 Src: 目标点 / 瞄准点 的组合(2025 E题「简易自行瞄准装置」)

| Src | 目标点 | 瞄准点 | 用途 |
|---|---|---|---|
| 0 | 最大色块 | 画面中心+AimOff | 原行为 |
| 1 | 靶心 | 画面中心+AimOff | 激光与光轴近似同心时 |
| **2** | 靶心 | **实测激光光斑** | ★静态打靶(基本要求2、3) |
| **3** | 靶心+6cm圆上动点 | **实测激光光斑** | ★发挥(3)画圆 |

**为什么 Src≥2 要实测光斑,而不是用 AimOff 常数**:激光装在相机外壳上,与光轴有高度差 b。
光斑像素偏移 = f·b/d,**随距离变**(b=3cm 时 d=50cm 偏 16px、d=150cm 偏 5px,绕场一圈差 11px ≈ 2cm,
把整个 D1≤2cm 的余量吃光)。实测光斑则误差 = 两个像素坐标相减 —— 与距离、镜头畸变、
激光装歪多少全无关。**量出来的,不是算出来的。**

`CircR`(px)= 画圆半径,`CircT`(s)= 转一圈秒数。光斑丢帧时 info 显示 `lz~`(用上一帧),
从没检出过显示 `NOlz`(退回 AimOff 常数)。

### 单轴也能验画圆
`Axes=2` 时 ey 自动收敛、ex 只显示不执行 —— **光斑的 Y 自动跟着圆走,X 你手动搬云台跟**,
两个人合力就能画出整圆。能验的:相位生成、CircR 标定、光斑检测、pitch 跟动点。
只剩 yaw 伺服没验,而它和 pitch 是完全对称的代码路径。

### ⚠ 激光笔选型(题目硬要求)
1. **必须 405nm 蓝紫激光。** 靶纸是紫外感光纸,评分看"光斑**痕迹**距靶心 D1≤2cm"。
   **红激光不留痕迹 = 没成绩。**
2. **红激光和靶上的红环同色。** 题目: "用**红色**记号笔标靶心,以此为圆心画 2/4/6/8/10cm **红色**圆"。
   红光只能靠"亮度饱和+小圆斑"的形态差异跟红环分开,很脆。换 405nm 后天然分色。
3. 红光**开发验证够用**,但 `laser_thr` 到时候要按 405nm 重调。

### ⚠ 待办: 画圆相位需要主控下发
题目要"小车1圈 = 光斑1圈,同步误差 <1/4圈"。相位应由**主控**(它在巡线,知道圈位置)下发,
但协议现在只有上行(0x80 SET_MODE / 0x81 PING),**没有这条下行**。
现在用本地计时(CircT)做静态验证够,真机前必须和队友把这条协议定了。

## 4. 屏幕 info 行标志

| 标志 | 含义 | 处理 |
|---|---|---|
| `LOCK` | 连续 10 帧对准(阈值 LockPx) | 正常, 可让主控蜂鸣 |
| `LIM` | 指令角顶到软件限位 | 多半是 InvX/InvY 反了; 或限位太小 |
| `noFB` | 初始化时收不到电机反馈 | 纯 TX 仍可跟踪, 但清零未校验——先跑 f32c_test.py 排查 |
| `no tgt` | 靶心检测丢失 | 云台保持原位; 回 TARG 页重调阈值 |
| `YAW-only` / `PIT-only` | 单轴模式(Axes≠3) | 另一轴不受控, 需机械固定 |

## 5. 内部速度环 PID 调参(负载重/过冲时)

若云台带相机负载出现超调, 需调**电机内部速度环 PID**(不是视觉外环 FKp/FKd):
- 协议里**没有** PID 指令, 必须用厂商 **Windows 上位机(BLDC-Control)** 经 USB-TTL 调。
- 上位机**一次只能调一个电机**, 调哪个就**拔掉另一个电机的电源线**再连。
- 参考范围: 速度环 KP 5~50, KI 5~100, 从小往大加(手册: 调大后空载会高频振动)。
- 调好后点"保存设备参数"掉电保存。

## 5.4 触屏怎么改参数(所有调参都在这里做)

屏幕底部一排按钮:

| 按钮 | 作用 |
|---|---|
| `<` `>` | **切换**当前参数(参数名+值显示在底部黄字) |
| `-` `+` | **增减**当前参数的值 |
| `SV` | **存盘**。★ 不按这个, 重启就回默认值! |
| `PICK` | 框选取色(调阈值用) |

GIMB 页参数顺序(进页面默认停在第 1 个 `Src`):

```
Src → CircR → CircT → Drv → PosMd → Axes → Dbg → FKp → FKd → FSpd → FStep → ...
 ↑                                           ↑     ↑
 按0次>                                   按6次>  按7次>
```

所以 **改 FKp = 进 GIMB → 按 7 次 `>` → 底部显示 `FKp` → 按 `+`/`-` 调 → 按 `SV` 存盘**。

⚠ 加参数会改变按几次的顺序。**别背次数,以底部黄字显示的参数名为准。**
顺序随时可以用 `python3 tools/check_params.py` 打出来(它同时会校验条目表和默认值表没脱节)。

改任何参数都会在终端打一行 `param: FKp = 0.035`, 以此为准 —— 进模式时那行 banner
只反映**进入那一刻**的值, 之后你在触屏上改的它看不到。

## 5.5 增益整定(重要: 这个环是 PI, 不是 PD)

`update()` 里指令角是**累加**的: `ang += FKp*e + FKd*(e-e_last)`。展开后:

```
ang[n] = FKp*(e0+e1+...+en)  +  FKd*e[n]
         ^^^^^^^^^^^^^^^^^^      ^^^^^^^
         乘的是误差累加和         乘的是当前误差
         => FKp 是【积分增益 I】   => FKd 是【比例增益 P】
```

**所以稳定性是 FKp 说了算。振荡 = FKp 太大, 降它, 别去加 FKd。**

积分环 + 环路延迟 d 帧 => FKp 有个硬临界值, 超了必等幅振荡甚至发散:

| 环路延迟 | FKp 临界(ppd≈4.9) | 临界时振荡周期 |
|---|---|---|
| 2 帧 | 0.204 | 0.24 s |
| 3 帧 | 0.126 | 0.40 s |
| 4 帧 | 0.091 | 0.56 s |
| 5 帧 | 0.071 | 0.72 s |

**默认已改为 FKp=0.02 / FKd=0** —— 对 1~4 帧的任意延迟都稳(|z|≤0.90), 先跑通再往上加。

### 别猜, 量出来
1. 触屏 GIMB 页 `Dbg` 设 1 → 每帧打印 `GIMBLOG,帧号,ex,ey,yaw,pitch`
2. 跑 5~10 秒(有振荡更好), 把 GIMBLOG 行复制存成 `log.txt`
3. 电脑上 `python3 tools/analyze_gimblog.py log.txt`

它会实测出 **ppd(每度多少像素)** 和 **环路延迟 d**, 直接算出 FKp 的临界值和推荐值。
(该脚本已用已知真值的合成日志验证过: ppd 误差 <2%, d 精确命中。)

⚠ 若报 `ppd 过小` → **相机没装在云台上**: 云台转了画面却不动, 闭环根本不成立。

## 6. 已知坑(来自代码考古 + 手册, 队友注意)

- MSPM0 参考工程里 `M1ADD/M1SUB`(`+= value*10`)和 `Gimbal_SetRelativeAngle`(`deg*10`)
  与 `M1POS`(`= value`)**单位不一致, 差 10 倍**。校对角度一律用 `M1POS`/`STATUS` 路径;
  视觉侧 `f32c.py` 直接按线上 0.1° 单位发, 不受影响。
- 线上多字节是**大端**, 而视觉↔主控协议是小端, 两边别搞混。
- **裸电机出厂默认 ID=2**; 云台已预设 X(YAW)=1、Y(PITCH)=2。改 ID 发 0x0D, 再发 0x08 保存,
  然后**断电重启**才生效。
- 重设电机永久零点(EEPROM)必须断 12V 重上电, RESET 无效。
- **相机跑着跑着重启 ≠ 代码 bug**: Python 异常只会打 traceback, 整机重启是电源/复位事件。
  先用 `f32c_diag.py` 分级排查(见脚本头), 别去改代码。
- **高速转动中禁止突然堵转**: 反充电压可能烧驱动器(手册注意事项)。软件限位 + 限速已降低风险。
- 供电范围 8~15V(推荐 3S), 12V 下最大可控 1000RPM; speed_rpm 默认 30 远在安全区。
